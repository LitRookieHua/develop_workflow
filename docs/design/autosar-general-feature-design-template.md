## 五、 异常处理、容错与安全机制 (Error Handling & Safety)
> 💡 *通用功能必须具备极高的鲁棒性，应对各种边界异常。*

| 异常/边界场景 | 潜在风险 | 通用防御与降级策略 |
| :--- | :--- | :--- |
| **非法参数输入 (Invalid Pointer / Range)** | 引发内存越界或系统崩溃 (`OS_ErrorHook`) | 在 API 入口处严格进行 `NULL_PTR` 检查及边界判定，错误时直接返回 E_NOT_OK。 |
| **核心资源冲突 (Race Condition)** | 多任务/中断并发修改共享全局变量导致数据脏读 | 采用 `SchM_Enter` / `SchM_Exit` 临界区保护，或通过锁机制隔离。 |
| **通信或硬件故障超时** | 状态机卡死在中间态无法恢复 | 引入独立的 Watchdog 监测或超时强行复位机制，确保系统最终能回到安全态。 |
